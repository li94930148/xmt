# XMT v2.13.6 发布说明

## 发布主题

Phase 2-C3-4 Auth v1 HTTP 灰度适配建设。

## API 列表

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/logout`
- `GET /api/v1/auth/sessions`

## Feature Flag

- `XMT_AUTH_V1_ENABLED=false`：默认值，v1 Auth 不挂载。
- 只有显式设置为 `true` 且 `NODE_ENV` 不是 `production` 时才可挂载。
- 启用测试必须配置独立的 `XMT_AUTH_REFRESH_PEPPER`，不得复用 JWT 密钥。
- `JWT_V1_ISSUER`、`JWT_V1_AUDIENCE` 可配置实验性 Access Token 的 issuer 和 audience。

## 契约与安全

1. 请求和响应由 `shared/schema/auth.schema.ts` 统一定义。
2. 成功响应使用 `{ success, data, meta.requestId }`，错误响应使用稳定 Auth 错误码。
3. OpenAPI 中四个接口均标记 `x-experimental: true`。
4. Refresh Token 原文不写数据库或日志；响应体交付只用于非生产内部测试。
5. 登录与刷新响应设置 `Cache-Control: no-store`。

## 兼容性

- legacy `/api/auth/*`、旧 JWT payload 和 7 天有效期不变。
- Login 页面、前端 token 存储、Cookie 和 Socket 认证不变。
- 不向生产用户开放或返回 Refresh Token。

## 数据库变化

无。继续使用 `auth_sessions` 和 `auth_refresh_tokens`，未新增 migration。
