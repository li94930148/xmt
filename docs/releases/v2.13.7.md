# XMT v2.13.7 发布说明

## 发布主题

Phase 2-C3-5-B Web Auth 迁移基础设施建设。

## 新增结构

- `src/auth/runtime/`：认证模式、状态机、内存 Token Store、刷新协调和 Runtime。
- `packages/api-client/auth-client.ts`：v1 login、refresh、logout、sessions 调用封装。
- `api/modules/auth/web/`：Cookie 配置、CSRF 服务、Web 开关与用户 ID allowlist。
- `tests/auth/auth-web-runtime.test.ts`：前后端基础设施专项测试。

## 能力边界

1. v1 Access Token 只进入新内存 Store，不写 localStorage/sessionStorage。
2. api-client 只有在调用方显式声明 v1 模式时才对 401 执行单飞 refresh，原请求最多重试一次。
3. Refresh Cookie 固定使用 `__Host-xmt_refresh`、HttpOnly、SameSite=Lax、Path=/，并提供设置和清除能力，但未接入路由。
4. CSRF Service 提供高熵 token、HMAC 签名、session 绑定及双提交验证，但未接入 refresh/logout。
5. `XMT_AUTH_WEB_ENABLED=false` 且生产强制关闭；未来测试还必须命中数字用户 ID allowlist。

## 兼容性

- `Login.tsx` 与 `src/api/auth.ts` 登录入口未修改。
- legacy `/api/auth/*`、7 天 JWT payload/有效期与 localStorage/sessionStorage Token 逻辑不变。
- v1 experimental 路由仍保持原非生产测试契约，未切换 Cookie 交付。
- Socket、Caddy、生产 Cookie 和生产 v1 Auth 均未修改。

## 数据库变化

无。继续复用现有认证表，未新增 migration，也未将 Cookie/CSRF/Runtime 接入数据库流程。

## 风险与下一步

- 当前 Runtime 是独立基础设施，尚无页面消费者；不得将其描述为 Web 已迁移。
- C3-5-C 应优先完成后端 Cookie/CSRF HTTP 适配与登录事务原子化，继续保持 Login 不切换，再进行浏览器契约验证。
