# XMT v2.13.8 发布说明

## 发布主题

Phase 2-C3-5-C Web Cookie / CSRF HTTP 适配。

## Cookie 变化

- 非生产 Web Auth 分支以 `__Host-xmt_refresh` HttpOnly Cookie 交付 Refresh Token。
- Cookie 使用 `SameSite=Lax; Path=/`、无 Domain；生产配置强制 Secure，本地测试可使用隔离配置。
- login 与 refresh 设置/轮换 Cookie；logout 使用同名同 Path 和 `Max-Age=0` 清除。
- CSRF Token 使用独立 `__Host-xmt_csrf` Cookie，并由前端通过 `X-XMT-CSRF` 回传。

## API 变化

- Web `POST /api/v1/auth/login` JSON 只返回 user、accessToken、session 和 expiresIn，不含 Refresh Token。
- Web `POST /api/v1/auth/refresh` 只从 Cookie 读取 Refresh Token；body Token 被拒绝，不做降级。
- refresh 校验受信 Origin、CSRF 双提交、Refresh hash 和 session，并在事务轮换后设置新 Cookie。
- Web `POST /api/v1/auth/logout` 验证 Access Token、session、Origin 与 CSRF，随后撤销 session 并清 Cookie。
- 上述接口继续标记 experimental，且仅在 v1/Web 双开关、非生产和用户 ID allowlist 同时满足时可用。

## 事务边界

Web 登录在单个 SQLite 写事务中创建 `auth_sessions`、generation 0 `auth_refresh_tokens` hash 和 `activity_log`。任一步失败整体回滚，不产生孤立 session；提交成功后才签发 Access Token 和设置 Cookie。

## 数据库变化

无。未新增表、字段、索引或 migration，只强化现有表写入的事务一致性。

## 兼容范围

- `Login.tsx`、legacy `/api/auth/*`、localStorage/sessionStorage、旧 JWT 和 7 天有效期不变。
- Socket、Yjs、Caddy、线上 Cookie 配置与生产 v1 Auth 不变。
- Web Runtime 尚未接入现有页面，因此普通用户操作无变化。

## 下一步

C3-5-D 建议进行非生产浏览器暗启验证：接入独立测试入口或测试夹具、验证 Runtime 冷启动/401/退出，但仍不切换正式 Login 或 Socket。
