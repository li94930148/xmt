# XMT v2.13.9 发布说明

## 发布主题

Phase 2-C3-5-D Web Auth 暗启验证与浏览器契约测试。

## 测试场景

- v1 Web 登录后，F5、新标签页和关闭重开均通过 HttpOnly Refresh Cookie 恢复认证。
- Access Token 失效后的五个并发请求只触发一次 refresh，其余请求等待并使用新 Token 恢复。
- Cookie 缺失、session 撤销、Refresh Token reuse 和 CSRF 失败均进入 expired，并清除内存 Token 与用户状态。
- logout 撤销服务端 session、清除 Cookie 和 Runtime；后续受保护访问要求重新认证。
- v1/Web 双开关、用户 ID allowlist 与非生产环境门禁全部通过。

## 浏览器行为

- Access Token 仅保存在内存，不写入 localStorage 或 sessionStorage。
- HttpOnly Refresh Cookie 无法被页面脚本读取；CSRF Cookie 可由客户端读取并通过 Header 回传。
- 页面重新加载后内存 Token 消失，由 Refresh Cookie 完成冷启动恢复。

## 数据库变化

无。自动化使用临时 SQLite，不修改现有数据库结构或业务数据。

## 兼容范围

- 正式 `Login.tsx`、`src/api/auth.ts`、Zustand Auth Store 与 legacy `/api/auth/*` 不变。
- 旧 JWT、7 天有效期、现有持久 Token、Socket、Yjs、Caddy 和线上 Cookie 策略不变。
- Web Auth 默认关闭且生产环境不可启用，本版本不承接真实用户流量。

## 下一步

C3-5-E 建议聚焦跨标签刷新协调、暗启可观测性与灰度准入/回滚清单；在明确实施指令前继续不切换正式登录入口。
