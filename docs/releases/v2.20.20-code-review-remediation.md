# XMT v2.20.20 代码审查安全整改

## 结论

本次逐项核验 `outputs/xmt-code-review-report.md` 的 9 个问题，不执行报告中的原始扫描或批量替换建议。H1、H2、W1、W2、W3、S1 和 S4 已按当前代码边界整改；S2 经核验为非缺陷，S3 依赖 Auth v1 完成迁移后再退役 legacy JWT，本次不改变认证协议。

## 修复内容

- Social Review 旧路由在自身入口统一执行 `authenticate` 与 `analytics:view`，避免未来重新挂载时漏掉账号、任务、错误日志或指标端点；登录会话、账号删除与计划管理仍额外要求管理员。
- Social Review 与总结归档只向客户端返回明确白名单内的业务错误。未知异常统一为 `INTERNAL_ERROR` 和固定安全提示，日志仅记录异常类型。
- 用户列表、操作日志和活动日志统一使用正整数分页；非法页码回退为 1，非法条数回退默认值，每页最多 200 条。
- 权限缓存 TTL 从 5 分钟缩短为 60 秒；角色和权限写路径原有 `clearPermissionCache` 主动失效不变。
- 工作流 4 处通知模板恢复为 `选题「${title}」...`，避免把占位文本直接展示给用户。

## 处置边界

- `api/routes/social-review.ts` 当前没有挂载到 `api/app.ts`，因此报告 H1 不是当前生产路由上的可利用越权；本次作为重新启用前的纵深防御完成修复。
- `req.user!` 的使用点当前均由认证或权限中间件保护，未进行全局类型重构。
- legacy JWT 的 issuer/audience 设计属于迁移期兼容边界。未在本次安全修复中提前下线，避免破坏尚未完成的 Auth v1 灰度。
- 无数据库迁移、无业务数据写入、无角色或权限分配变化、无生产部署。
