# XMT v2.20.21 共享用户模型精简与清理核验

## 结论

本次将 `outputs/xmt-code-cleanup-plan.md` 视为待验证候选清单，而不是删除指令。完成当前调用链、测试入口、文档语义和未提交工作核验后，只实施两项可以证明不改变业务行为的清理：移除共享用户对象的密码字段；删除无生产调用的认证模式解析函数。

## 已实施

### 共享用户对象不再携带密码

- `shared/types/index.ts` 的前后端共享 `User` DTO 删除 `password`。
- `api/middleware/auth.ts` 不再向 `req.user` 填充空密码。
- Legacy 和 v1 Web 登录响应适配都不再复制或创建密码字段。Legacy 响应即使意外出现 `password`，适配后也会丢弃。
- 后端认证仓储的专用 `UserRecord.password` 保持不变，仅用于密码哈希校验，不进入共享 DTO。

### 删除认证模式死函数

- `resolveAuthMode()` 没有生产调用点，仅有一组专项测试直接调用，因此删除函数及过时断言。
- `AuthMode` 类型仍被 Auth Runtime 和状态模型使用，继续保留。

## 核验后保留

- Social Review：后端旧路由虽未挂载，但前端仍有 4 个页面路由、完整 API 客户端、Socket 登录会话所有权判断和多组诊断/验收脚本。是否完整退役属于产品能力选择，不能按后端单点引用结论直接删除。
- `api/utils/jwt.ts`：当前仍有应用入口、认证中间件以及测试/脚本共 20 个调用文件。两行兼容转发避免调用方直接耦合模块内部路径，删除收益不足以覆盖改动面。
- `douyin_snapshots`：历史数据回填脚本仍读取；`editing`：架构文档明确要求冻结观察；其他遗留表在没有生产备份和数据审计前不执行 DROP。
- Auth 灰度、Topics 双轨及其测试：仍处于当前迁移合同的保留期。
- 调试、冒烟、回填、备份和 Topic HTML 迁移脚本：多项仍由 `package.json`、测试或迁移文档引用，未进行批量删除或移动。

## 影响与回滚

- 无 API 路由、响应 envelope、数据库、权限、登录流程、Token 或 Session 变化。
- 回滚仅需恢复共享 `User.password`、三处空字段投影以及 `resolveAuthMode()` 与对应测试；不涉及数据恢复。
