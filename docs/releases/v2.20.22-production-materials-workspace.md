# XMT v2.20.22 创作资料工作区

## 范围

本版本只改造创作详情页的资料整理区域，不改变正式稿件的 Tiptap/Yjs 协同文档、版本历史、审核状态机、时间轴或发布链路。

## 数据与 API

- migration `010_production_materials_workspace` 新增 `production_materials`，以创作为边界保存资料库快照或手动资料。
- 历史 `resource_relations` 中的 production/reference 关联幂等回填；可读取的 `resources.content_text` 原样保存为 `plain_text`，空内容保持为空。
- `GET /api/productions/:id/materials` 返回完整资料正文；旧 `GET /resources` 标题列表继续兼容滚动部署。
- `POST /api/productions/:id/resources` 支持最多 50 条资料库 ID，事务内同时写兼容关联和快照。
- `POST /api/productions/:id/materials/manual` 新建手动资料。
- `PUT/DELETE /api/productions/:productionId/materials/:materialId` 只操作目标创作内的快照。
- 更新通过 `revision` 乐观锁拒绝旧请求；标题最多 200 字符，正文原始 HTML 最多 500,000 字符，全局 JSON 请求体仍受 16 MiB 上限保护。

## 权限与安全

- 查看要求 `production:view`、真实创作可见范围和有效登录。
- 修改要求 `production:update`、真实创作可编辑范围且稿件未审核锁定；从资料库添加额外要求 `resource:view` 和资源 scope。
- 服务端使用白名单 HTML 清洗，仅保留常用段落、强调、列表、引用、代码和 HTTP(S)/mailto 链接；客户端展示前再次清洗。
- 正文不写入资源审计详情或错误日志。删除来源快照不会删除资料中心原文。

## 前端交互

- 资料卡在当前页直接展示正文，阅读区只有一个纵向滚动容器。
- 手动资料与快照编辑均通过统一 `ContentEditor mode="rich"`，不加入正式稿件协作 room。
- 自动保存延迟 800ms；请求串行提交，失败保留草稿并提供重试，离页时有浏览器未保存提示。
- 工作区默认 360px，高度限制为至少 240px、至多视口 75%；pointer 拖动、方向键调整和双击复位均按用户写入本机 localStorage。

## 回滚与部署边界

迁移为扩展式新增并保留旧 `resource_relations`。旧应用可忽略新表；代码回滚不要求删除新表。本轮只创建代码、测试、提交和 PR，不部署生产。正式部署前仍需执行数据库备份、migration readiness、SQLite 完整性和精确 SHA 门禁。
