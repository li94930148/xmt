# XMT v2.20.23 统一创作资料草稿

## 范围

创作详情页的“创作资料”收敛为一份连续的 Tiptap 富文本草稿。删除资料卡片、单条操作、数量角标、“新建手动资料”和添加按钮二级菜单，不改变正式稿件协同文档、版本历史、审核、时间轴或发布流程。

## 数据与兼容

- migration `011_production_material_draft` 新增 `production_material_drafts`，每篇创作至多一行，使用 revision 乐观锁。
- 已部署的 `production_materials` 按 `sort_order,id` 合并；空正文跳过，不同正文之间保留两个空行。
- migration 通过正式迁移记录与 `INSERT OR IGNORE` 保持幂等，不重复追加；旧表和旧数据不删除。
- `GET/PUT /api/productions/:id/material-draft` 读取和保存统一草稿。
- `POST /api/productions/:id/material-draft/resources` 按请求顺序返回资料库正文副本，并单独报告空正文 ID。
- v2.20.22 的卡片 CRUD 与手动资料接口不再挂载，避免继续产生分块数据。

## 权限与安全

- 查看继续要求 `production:view` 与创作可见范围。
- 保存及插入继续要求 `production:update`、真实可编辑范围且稿件未审核锁定；资料插入额外要求 `resource:view` 和资源 scope。
- 草稿原始 HTML 上限 500,000 字符，服务端再次执行白名单清洗；资料库正文按纯文本安全转换。
- 插入与后续编辑均不修改资料库原文，也不写入正式稿件版本或协作 room。

## 前端交互

- “添加资料”直接打开现有资料库选择窗口；多选正文按选择顺序插入。
- Tiptap 记录最后有效选区；能够恢复时插入光标位置，否则追加到文档末尾。
- 草稿始终可直接输入或粘贴，800ms 串行自动保存；失败保留内容并提供重试。
- 保留 360px 默认高度、240px 最小高度、75vh 最大高度、pointer 拖动、双击复位、键盘调整与按用户保存。

## 发布边界

本轮完成代码、测试、中文提交和 PR，不部署生产。部署前必须备份当前 SQLite，验证 migration 011、Restore Drill、精确 SHA、PM2、Caddy 和公网健康检查。
