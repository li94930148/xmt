# XMT v2.20.25 创作只读与首页数据联动

## 范围

本版本修复已审核稿件再次打开时创作资料仍触发自动保存的问题，并把首页内容生产驾驶舱接入现有选题、创作、发布与抖音运营数据。不改变稿件审核锁、版本历史、资料草稿存储或 Creator Agent 同步协议。

## 已审核创作资料

- 服务端继续以 `production.status = approved` 返回 423，作为不可绕过的只读保护。
- 前端在 `canManage = false` 时不接收编辑器 `onChange` 为待保存内容，并清理定时器、排队保存和卸载补保存。
- 只读态不展示保存重试入口；资料正文仍可查看和复制。

## 首页聚合口径

- 待审核来自完整选题列表；创作中来自处于 production 阶段的选题与未审核创作记录；待发布来自 publishing 阶段选题与未发布记录。
- 已完成内容按创作审核通过或发布完成的唯一选题计数，重复记录不重复累计。
- 内容生产指数以选题为粒度取最深阶段：待审核 0、已通过 25、创作 45、成片 65、待发布 80、发布完成 100，再计算所有可见选题的平均值。
- 播放量优先使用抖音运营中心 `metrics.play_count`；无 Creator 数据查看权限或暂无可用账号数据时，回退既有月度分析统计。
- 所有列表与抖音请求并行执行，单一来源失败不会阻断首页其他可用数据。

## 数据与权限

本版本无数据库迁移，不修改现有选题、稿件、资料、发布或抖音作品数据。各来源继续沿用自己的登录、内容可见范围、`analytics:view` 和 `creator:data:view` 权限门禁。

## 验收边界

专项测试覆盖只读态不调度保存、首页阶段去重与指数计算。正式环境仍需使用有真实 Creator 数据的账号核对首页累计播放与抖音运营中心一致，并在浏览器网络面板确认打开已审核稿件不产生 material-draft PUT 请求。
