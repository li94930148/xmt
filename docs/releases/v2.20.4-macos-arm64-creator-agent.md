# XMT v2.20.4 macOS arm64 Creator Agent 发布说明

## 目标与版本

- System：`v2.20.4`
- Creator Agent：`v2.13.0-agent`
- 产物：`XMT Creator Agent.app`、`XMT-Creator-Agent-v2.13.0-macos-arm64.zip`
- 构建身份：`macos-arm64-v2.20.4-v2.13.0-agent-<git-sha>`，由包内 `Resources/build-info.json` 提供。

## 运行资源与安全边界

- 正式态只从 `process.resourcesPath` 读取 PyInstaller `collector-runtime`；不会回退到仓库 `collector/.venv`、Node、npm 或系统 Python。
- Renderer 为 Electron 打包静态文件，运行身份会展示 `Packaged`、Build ID、数据库 / `upload_queue` 状态与 API 分类，但不展示 Token 或服务地址。
- 包构建不包含配置、受管 Profile、Cookie、Token、SQLite 数据库、XLSX、日志或生产密钥；CI 与本地契约均扫描这些类型。
- 数据继续位于 macOS 标准 Application Support userData 位置。首次启动只执行可重入的 `upload_queue` 初始化；不得覆盖既有配置或 Profile。

## 本地验证契约

`npm --prefix agent run test:package-runtime:mac` 会从 ZIP 解压到独立临时位置，以最小 `PATH` 启动 `.app`，并确认：

1. 主进程 `app.isPackaged === true`、静态 Renderer 与 `resourcesPath` 一致；
2. 数据库 ready barrier 与 `upload_queue` 已完成；
3. 仅启动包内 arm64 PyInstaller Scrapling Worker，health 返回 ready；
4. 不出现仓库绝对路径、用户数据或开发服务器依赖。

正式生产同步另行执行：必须先完成 PR/CI/合并/服务端健康门禁，再由用户在打包 UI 点击一次“开始同步”。

## 签名与发布状态

本机未发现 Developer ID Application 身份时，构建使用 ad-hoc 签名用于本地完整性验证：

```text
SIGNING_STATUS=AD_HOC
NOTARIZATION_STATUS=NOT_NOTARIZED
PUBLIC_DISTRIBUTION_READY=否
```

必须记录 `codesign --verify --deep --strict --verbose=2`、主程序与 Worker 的 `file` 架构结果及 `spctl --assess` 结果。ad-hoc 包可作为内部验证 artifact，不能伪称已公证或可公开分发。

## 回滚

保留原 Agent 数据目录中的数据库与必要配置一致性备份及 SHA-256。出现迁移、绑定、Profile、队列或生产归属异常时：停止同步、关闭 Agent、以备份恢复本地数据；服务端按已记录 SHA 与数据库备份执行独立回滚。不得删除原 Profile 或使用测试副本覆盖真实数据。
