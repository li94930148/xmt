# XMT v2.20.5 Creator Agent 登录状态一致性发布说明

## 范围

- System：`v2.20.5`
- Creator Agent：`v2.13.1-agent`
- 不新增服务端数据库迁移，不改变 v1/v2 上传协议、nonce 防重放、受管 Profile、Chrome CDP 或队列模型。

## 根因与修复

此前 Dashboard 用 React 本地 `loginOpen` 决定“我已完成登录”，而 Main 只保存进程内 `activeSession`。窗口关闭或 Main 重启时，Renderer 的旧布尔值没有被 Main 状态覆盖，因此可在没有会话时调用 `agent:login-complete`。浏览器卡片又以不含 custom path 的发现结果匹配配置 ID，已实际解析的自定义浏览器可能显示“未选择”。

v2.20.5 将登录流程固定为 Main 权威状态机：`idle`、`opening`、`awaiting_confirmation`、`authenticated`、`closed`、`error`。只有 Main 确认受管浏览器窗口仍存活且处于 `awaiting_confirmation` 时才允许确认；否则稳定返回 `LOGIN_WINDOW_NOT_OPEN`。Renderer 每次加载都读取 Main 状态，不再保存登录窗口状态，并将 IPC/驱动错误映射为脱敏中文提示。

## 验证与回滚

- 已覆盖未开窗口确认、窗口关闭、Main 重启、已登录 Profile、Renderer 刷新、无浏览器禁用、SQLite queue/database-ready 和包内 arm64 Playwright driver。
- 正式包仍从 `process.resourcesPath` 使用自包含 Worker；不包含数据库、Profile、Cookie、Token、XLSX、日志或密钥。
- 如出现异常，停止同步并使用已有 Agent 数据和配置备份恢复；不得清理或覆盖受管 Profile。服务端按安全部署记录的 SHA 和数据库备份独立回滚。
