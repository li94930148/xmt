# v2.21.0 发布管理与抖音数据关联

## 目标

打通发布管理与抖音运营中心。发布稿件与已采集抖音作品建立明确关联后，发布时间、发布状态和互动指标以抖音运营中心为准，同时保留发布阶段正文、排期和历史数据。

## 数据模型

migration 013 新增 `publishing_douyin_links`：

- `publishing_id` 是主键并外键关联 `publishing`；
- `douyin_work_id` 唯一并外键关联 `douyin_works`；
- `match_method`、`match_score` 记录自动或人工关联依据；
- 删除任一侧业务记录时仅级联删除映射，不删除另一侧记录。

该表不保存作品指标，不把抖音值反写到 Publishing。每次读取发布列表或详情时，已关联记录实时 JOIN `douyin_works`；未关联记录继续回退到 Publishing 与 Analytics 原有值。

## 匹配规则

1. 标题先执行 Unicode 归一化、大小写统一和非文字数字字符移除。
2. 完全相同或抖音标题中的明确标题片段优先匹配。
3. 包含与模糊匹配必须同时满足最低分、最小有效标题长度和第一、第二候选分差。
4. 同一作品竞争多条发布记录、同分候选或分差不足时不自动写入。
5. 名称修改较大、短标题或同名作品由有权限用户搜索候选并人工确认。

## 数据权威口径

已关联记录的平台、状态、发布时间、播放、点赞、分享和评论来自 `douyin_works`。发布稿件正文、URL、原始平台、原始状态、排期和旧统计继续保留。解除关联后立即恢复原数据，不进行破坏性回填。

## 权限与安全

- 查看候选需要 `creator:data:view`，并受发布记录对应选题的数据范围限制。
- 自动刷新或修改关联同时需要 `workflow:publishing` 与 `creator:data:view`；人工绑定还要求该稿件可编辑范围。
- 候选搜索关键词最多 200 个字符，避免异常输入放大模糊匹配计算。
- 未知内部异常只返回固定安全提示，不向浏览器暴露 SQL 或服务错误文本。
- 同步已提交成功后才执行关联协调；协调失败只记录脱敏日志，不回滚或伪装抖音同步结果。

## 验收范围

- 标题归一化、完全/包含/模糊评分和歧义拒绝；
- 同步后自动关联与唯一性冲突；
- 发布列表/详情读取抖音实时指标；
- 抖音指标更新后发布页同步变化；
- 人工绑定、解除绑定及原数据回退；
- API 权限、SQLite 外键、完整性与 migration 幂等性；
- TypeScript、版本治理、生产构建和真实浏览器页面。

## 发布边界

本代码完成不等于生产部署。上线必须先备份并验证生产 SQLite，运行 migration readiness，按合并后的精确 SHA 发布，再在真实账号下执行关联刷新和抽样核对。自动匹配未覆盖的历史记录应人工确认，不得用标题批量删除或强制合并数据。
