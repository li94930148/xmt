# v2.21.1 发布与分析数据一致性修复

## 目标

修复发布管理与旧分析数据在多日期、分页、部分更新和抖音关联状态下的不一致，同时保持现有表结构、历史记录和抖音权威数据不被改写。

## 读取口径

- 每条发布记录最多返回一次。
- 已关联抖音作品时，继续以 `douyin_works` 的平台、状态、发布时间和互动指标为准。
- 未关联时，旧 `analytics` 回退只读取该选题最新 `data_date` 的记录；日期相同时选择最高 ID，保证结果确定。
- 列表总数和状态汇总使用同一权限、选题筛选与关联口径；汇总不受当前分页限制，“今日”使用北京时间。

## 写入边界

- 新建发布记录只累加同一选题、同一数据日期的指标，不更新其他日期。
- 编辑发布指标只修改显式提交的字段，其他指标保持原值；只修改发布时间不会移动或覆盖历史分析记录。
- 发布记录、当日指标以及完成状态/消息在同一数据库事务中提交。
- 发布主事务成功后的资源归档协调若失败，会记录脱敏错误并保留已成功的发布结果，避免向用户返回伪失败。

## 权限与校验

- 分析写入继续要求 `analytics:create`，并新增选题存在性和当前用户数据范围校验。
- 日期必须是有效 `YYYY-MM-DD`，播放、点赞、分享和评论必须是非负安全整数。
- 已关联抖音作品时，API 拒绝修改平台、状态、发布时间和互动指标；URL 与正文等非权威字段仍可维护。

## 数据库变化

无 schema migration。不删除、不合并、不回填现有 `analytics`、`publishing`、`publishing_douyin_links` 或 `douyin_works` 数据。

## 验收

- 两条不同日期的分析快照不会把一条发布复制成两行，分页总数保持为一。
- 旧日期指标不会被新建或编辑发布操作覆盖。
- 部分指标更新保留未提交指标。
- 抖音关联后的权威字段绕过页面调用 API 时返回冲突。
- 分析写入越权、非法日期和负数被拒绝。
- 页面统计覆盖完整可见数据，并按北京时间识别今日。
