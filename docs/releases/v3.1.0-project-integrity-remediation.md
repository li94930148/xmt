# v3.1.0 项目完整性整改

依据用户提供的 `project-integrity-audit.md` 审计报告逐条回查当前源码。审计文档中的阶段范围与建议不是本次实现指令；以现有调用链和数据契约为准。

## 本阶段已修

| 审计项 | 结果 |
| --- | --- |
| F-D1-01、F-D1-02、F-D10-02 | 强制改密服务端 403；权限检查统一由角色授权表决定，内置账号缺失映射时补齐；`/api/auth` 进入共享限流。 |

| F-D7-01、F-D7-02（部分） | Collector 把脱敏且有上限的 XHR 记录送入 Agent 快照；本地看板、粉丝、原始响应缺失时状态为失败。旧统一上传协议可读取快照 captures。 |

## 边界和后续

- 采集端的官方四文件上传走独立 v2 协议，本次未把 XHR 原始记录并入该协议；不能声称正式官方导出已经产生 `raw_records`。未做真实账号采集。
- 社媒复盘原后端因迁移故意未挂载；本次关闭前端死入口，未恢复旧服务或删除历史数据。
- 审计报告中的权限词表归并、生产记录分页、历史数据重构、模板和移动端等其他条目仍需按调用链逐项实施，不能以本版本标记为全部完成。
- 本次不直接改现有生产数据库，也未部署。新建数据库启动时会补齐四个内置账号缺失的角色映射。
