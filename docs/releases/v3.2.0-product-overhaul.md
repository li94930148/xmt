# v3.2.0 产品工作流全面改造

## 目标

依据 2026-09 产品改造清单，将首页从展示型看板改为可行动工作台，优先修复灵感、选题、创作主链路中的真实断点，并收敛导航、跨主题显示、移动端文案和设置页技术信息。

## 已完成

- 工作台按当前角色聚合今日任务、逾期提醒、七阶段内容流和最近变化，取数使用有界并行请求。
- 灵感转为选题后记录关联编号并进入选题详情；审核通过的选题可创建或进入已有稿件。
- 创作列表更新改用更新接口，带入旧正文进行冲突保护，普通编辑不创建新版本。
- 创作列表 API 增加兼容式分页、精确总数和权限同口径计数；列表页面使用每页 20 条服务端分页。
- 日常导航收敛为工作台、内容生产、资料与资产、运营数据、系统管理五组；命令面板复用相同权限来源。
- 旧资料入口统一跳转资产中心；消息单条已读失败不再静默；移动端状态和角色使用中文。
- 设置页使用业务语言，不再展示框架、通信实现和数据库文件路径；历史模糊更新说明改为具体业务描述。
- 编辑器菜单层级、亮暗主题表面、状态标签和空态继续复用 Studio Atelier 令牌。

## 兼容与数据边界

- 未传 `page` 或 `limit` 的创作列表调用继续返回旧数组格式，避免影响既有详情和兼容调用。
- 无数据库迁移，不删除、合并、批量回填或改写既有选题、稿件、发布和历史记录。
- 看板、日历和成就页保留兼容路由；成就不再占用日常导航。
- 未改动 Yjs 协作底座、正式稿件来源模型或生产状态迁移。

## 后续边界

- 看板与日历目前仅归入同一内容生产导航组，尚未物理合并为选题页视图。
- 稿件单一事实源、流程状态合并、离线草稿与同步队列、完整移动审批流属于高风险后续阶段，需要独立的数据迁移、权限和多人协作验收。
- 本次未部署正式环境；合并后仍需按精确提交执行备份、数据库完整性、权限角色和主链路验证。
