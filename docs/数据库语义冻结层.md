# 数据库语义冻结层

本文档用于冻结当前数据库语义边界。v8.0.0 使用 SAFE_EXPAND 迁移新增成片/发布剧本来源字段，v8.1.0 使用 SAFE_EXPAND 迁移新增创作初稿大纲来源快照，v9.0.0 使用 SAFE_EXPAND 迁移新增工作流文稿版本快照表，v9.0.1 使用 SAFE_EXPAND 迁移新增创作初稿来源版本标识；v9.0.2 展示已有逐版本来源字段；v9.0.3 让创作历史清理与删除检查成片/发布逐版本来源引用；v9.0.4 只增加已有大纲历史的只读跳转；v9.0.5 只展示归档中已有的来源关系与快照，不改动数据库结构。这些变更不删除或合并历史分析行，也不回填来源或版本身份未知的旧记录。发布管理读取旧分析数据时仍按最新日期、同日期最高 ID 确定一条回退快照。

## 真实源字段

当前系统真实内容源字段为：

1. `production.content`
2. `topics.outline`
3. `topics.description`
4. `shooting.script_content`
5. `publishing.script_content`

其中：

1. `production.content` 是唯一创作正文源。
2. `topics.outline` 是选题大纲源。
3. `topics.description` 是选题描述源。
4. `script_content` 是 Shooting / Publishing 各阶段的本地内容源。
5. `shooting.script_source_production_id` / `script_source_version` 与 `publishing.script_source_production_id` / `script_source_version` 是可空的来源追溯字段，不是正文源。
6. `production_origin_snapshots.source_content_snapshot` 是新建创作稿时的初稿来源凭据，不是当前正文源；它只记录创建时被引用的大纲，不参与后续正文读写。`source_outline_version` 只在创建快照时与唯一一条显式大纲版本精确匹配时记录，否则为 NULL。
7. `workflow_document_versions.content` 是选题大纲、拍摄剧本和发布文稿的只读版本快照，不是上述 canonical 正文列的替代品。

## 工作流文稿版本历史

1. canonical 内容仍保存在 `topics.outline`、`shooting.script_content` 和 `publishing.script_content`；不通过版本表反向恢复或覆盖当前文稿。
2. 只有用户明确选择保存小版本/大版本时才增加版本；普通保存、自动保存和状态变化不生成版本。
3. 首次显式创建版本时，系统在同一事务保存当前内容作为“未记录版本”的基线快照，再保存新版本。
4. 旧内容虽可作为基线展示，但其原始时间和操作者无法确认，因此 `created_at` 与 `operator_id` 保持 NULL，不得伪造时间或身份。
5. 迁移 029 仅创建新表和索引，不回填历史；来源创作版本引用仅作为追溯信息，不改变阶段文稿自身内容源。
6. 删除选题、拍摄记录或发布记录时，在对应删除事务中清理其版本快照。
7. 成片/发布剧本历史行的 `source_production_id` 与 `source_production_version` 描述该条历史保存时的创作来源；卡片只读取该历史行，不用当前阶段稿来源补写旧历史。来源未记录时保持 NULL 并在界面说明。
8. `resources` 中的“已完成”发布归档仍是每个选题可更新的最新快照，不是每个发布剧本版本的不可变归档；准确发布剧本版本从工作流文稿历史读取。显式创建发布版本后，发布接口仍刷新该最新快照，并通过现有漂移检测确认快照与线上 `script_content` 一致。

## 创作资料草稿与正式正文

1. `production_material_drafts.content_html` 是按创作记录隔离的资料整理草稿，不是正式正文源，也不会自动拼接、覆盖或回写 `production.content`。
2. 从资料库加入创作资料草稿时，在草稿 HTML 中保存复制的正文和本站来源链接；链接标识 `resource_id`，复制的正文则保留插入时文本。之后修改资料库原文不会静默改写已保存的草稿。
3. 只有用户明确选择“引用到正文”时，资料内容和来源链接才进入 `production.content`。正文仍仅由创作编辑器正式保存路径维护。
4. 现存无来源链接的旧草稿不推测补写来源；不新增关系表或迁移。

## 创作初稿来源快照

1. 通过选题进入创作或由工作流阶段自动创建创作初稿时，系统在同一事务记录被复制的 `topics.outline` 原文快照，关联到创建出的 `production.id`。
2. 该快照只用于解释“初稿创建时基于什么”，不跟随选题大纲或创作正文后续修改，也不覆盖 `production.content`。
3. 手工新建稿件只有显式声明来源为 `topic_outline` 且服务端事务内确认提交内容仍等于当前大纲时才记录；大纲已变化则返回冲突，不留下创作记录或错误快照。
4. 迁移 027 仅增加 `production_origin_snapshots` 表，迁移 030 仅增加可空 `source_outline_version`，均属于 SAFE_EXPAND；不推断或回填旧稿来源或版本。旧稿缺少记录时继续显示“来源未记录”，不以当前大纲冒充历史来源。
5. 来源版本关联仅接受与来源快照文本完全一致且唯一的非基线显式版本；只有基线、没有匹配版本或多个版本正文相同均保持 NULL，不以最新版本推测。

## 独立剧本来源

1. `script_content` 为 `NULL` 时表示没有建立阶段独立稿，可读取已审核创作稿；空字符串是已保存的空白独立稿，不得 fallback。
2. 来源编号与版本必须同时存在，并指向同一选题下当前或历史的已审核创作版本。
3. 已记录来源不随创作版本继续更新而漂移；历史版本来源仍可通过 `production_id + version` 反查。
4. 迁移 026 只添加四个可空字段，属于 SAFE_EXPAND，不回填历史来源，不改写任何剧本。
5. 已被成片/发布阶段稿引用的创作历史版本不参与自动历史清理；仍有阶段稿引用的创作记录不能删除。
6. 发布归档记录 `script_sources`（topic_id、production_id、version、来源状态）和去重后的 `script_source_snapshots`（精确来源正文），不依赖线上历史行仍保留才能查看既有归档。

## 发布与抖音关联

`publishing_douyin_links` 是发布记录与抖音作品之间的一对一映射，不是内容源，也不复制运营指标。

1. `publishing.script_content`、原始平台、排期和状态继续属于发布阶段本地事实。
2. 已关联记录在发布管理中的展示时间、发布状态、播放、点赞、分享和评论以 `douyin_works` 为权威来源。
3. 关联解除后恢复使用 `publishing` 与既有 `analytics` 数据。
4. 自动关联只写入高置信且无歧义的候选；不得按标题删除、合并或覆盖任一侧记录。
5. `publishing_douyin_links` 的两个外键分别保证每条发布记录和每条抖音作品最多参与一个关联。

## 过渡字段

以下 Markdown / JSON 字段全部为过渡字段，不得作为可靠 canonical：

1. `content_markdown`
2. `content_json`
3. `outline_markdown`
4. `outline_json`

禁止在未完成专项迁移前，将这些字段作为主读写来源、审核事实来源或版本事实来源。

## Workflow 观测表

`workflow_shadow_logs` 只增不改。

1. 用于记录 shadow、analytics、decision 和 strict gate 相关观测信息。
2. 不做 event sourcing。
3. 不作为业务状态回放事实源。
4. 不替代 `approval_records`。
5. 不在本阶段变更 schema。

## 审批记录表

`approval_records` 是审批业务事实。

1. 当前不做 policy 字段结构化改造。
2. 当前不新增 `policy_checked`、`policy_mode`、`transition_allowed`、`approve_allowed` 等字段。
3. 如后续要结构化记录 policy metadata，必须单独评估 schema、历史数据和回滚策略。

## 系统模型

当前系统仍为状态驱动模型，不是 event sourcing 系统。

1. `topic.status` 仍是业务状态判断的重要来源。
2. workflow templates 与 approval runtime 仍由现有业务表和接口语义决定。
3. `workflow_shadow_logs` 只提供观测和排查能力。
4. Strict Enforcement 是执行前 gate，不是数据库事件溯源引擎。

## 选题阶段进入时间

`topics.stage_entered_at` 是当前 `topics.status` 的显式阶段起点，仅用于展示阶段停留时长，不参与权限、状态迁移判断或历史回放。

1. 新建选题（包括灵感转选题）记录初始阶段进入时间；审核和标准/自定义工作流等真实状态变更在同一事务更新该字段。
2. 普通标题、描述、大纲、负责人等内容修改不重置阶段时间。
3. 字段为 NULL 的存量记录代表起点无法可靠确认，不得根据混合时间来源的 `topic_history.created_at` 或普通 `updated_at` 回填；UI 应显示待确认而非虚构时长。
4. 迁移 025 仅增加可空列，属于 SAFE_EXPAND；回滚到忽略此列的旧应用无需删除字段。
