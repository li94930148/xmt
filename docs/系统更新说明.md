# XMT 系统升级说明

## 当前版本 v3.3.43

同一选题、同一类型的桌面提醒在五分钟内会合并更新，后续提醒不再重复播放提示音。点击桌面通知会先校验站内链接，再打开关联业务页；站外链接会退回消息中心。消息记录仍逐条保留，不改动未读状态或数据库。

## 历史版本 v3.3.42

移动消息加载失败且没有缓存时现在会明确显示错误并可重试，避免和真实空列表混淆；未读标记失败或离线时会留在消息页显示反馈。移动账号页修改密码增加必填及至少 6 位检查，并在提交时禁用重复操作，成功提示会保留在页面上；服务端密码规则不变。

## 历史版本 v3.3.41

移动端在同一设备切换账号时，只恢复当前账号的消息缓存、选题、稿件和日报本机草稿。旧版未标注账号的本机数据不会自动显示，也不会被自动删除；如需找回旧草稿，应先由账号持有人确认归属。服务端权限和业务数据未改变。

## 历史版本 v3.3.40

移动首页、选题列表/详情、创作列表及拍摄/发布列表/详情遇到未知状态时会显示“状态待确认”，不会暴露内部状态码或留白；未知选题状态使用中性样式。Android 工程版本及生产端点清单同步为 `3.3.40 / 30340`。权限、业务流程和数据库均未改变。

移动日报现在会明确显示草稿、审核中、已通过、已退回或已归档。日报被退回时可以直接看到审核意见；审核通过和归档后会明确提示只读，并继续展示服务端已确认内容，不会把本机未提交草稿覆盖到已审核日报。日报权限和服务端流程没有变化。

移动账号页为文案、后期和摄像岗位显示各自中文名称；Android 工程版本同步到 3.3.38 / 30338。未调整权限。

移动选题详情不再反复加载，选题编辑权限用户可以稳定操作；创建和审核失败时显示服务端具体原因，输入内容可保留并重试。无数据库迁移，权限规则未变。

移动创作详情按照服务端计算的可编辑范围展示操作。无稿件编辑范围的负责人仍可查看，但编辑器只读且没有保存/提交按钮；服务端权限规则未变，无数据库迁移。

## 历史版本 v3.3.35

移动日报草稿保存成功、提交失败时会保留最新版本号，恢复后可直接重试，不再因旧版本号冲突。无数据库迁移。

### v2.20.15 · 依赖安全与工程化收口

- 修复 `@tiptap/*` 富文本编辑器 `mergeAttributes()` 在 `__proto__` 上把自有键变成可继承可执行 DOM 属性的中危漏洞；所有 `@tiptap/*` 包升级到 3.31.x。
- 修复 `qs` 在 express / body-parser 链路上的数组上限绕过与 `isBuffer` DoS 中危漏洞；`package.json#overrides` 将 `qs` 锁定到 6.16.0。
- 新增 HTTP 级错误脱敏拦截器回归测试：起真实应用实例、注入探针路由触发 5xx，断言页面响应里不再出现 SQL、字段名或绑定参数。任何后续改动若误删应用层出口拦截器，本测试会立刻失败。
- 新增 `api/utils/limits.ts` 统一请求体与同步包体积上限。`api/app.ts` 全局 413 文案与 `creatorSyncV291.ts` 同步包 413 文案均改为引用同一常量，再不会出现"12MB"与"16MB"两种提示并存。
- 抖音官方导出 xlsx 解析在展开前用 `sheet['!ref']` 判断行 / 列数，命中限制直接抛错，避免把整张表展开成内存数组才校验。
- 清理 `api/services/creatorDataCenter.ts` 中长期未被引用的 `acceptCreatorDataSync` 死代码副本，避免与 `creatorSyncV291.ts` 同名实现长期并存导致后续改错。
- 成就进度接口按 `condition_type`（`login_streak` 额外按时间窗）聚合缓存查询，成就数量增加时不会再退化成逐条 `COUNT(*)`。
- 新增 `deploy/linux/HTTPS_REQUIRED.md`，明确 `upgrade-insecure-requests` CSP 指令要求 XMT 必须部署在 HTTPS 站点之后；`docs/上线前检查清单.md` 同步补充对应章节。

无数据库迁移、未变更对外 API 行为；`package-lock.json` 同步更新后请运行 `npm ci` 刷新本地依赖。

- 建立 React Bits 官方组件、Typed Adapter、Semantic Slot 与 Page Scene 的统一视觉架构，页面视觉与业务逻辑进一步解耦。
- 首页、选题、日报、Creator、Analytics、Workflow、Editor 与 Settings / Appearance Center 完成场景化视觉升级。
- 提供岚曜极光、深空科技、丝绸创意、线性协作、极简无扰、自由搭配六套视觉方案，支持页面应用范围、动效级别、深浅主题、界面字号与高级参数。
- Appearance Center 完成 Scene Preview、配置导入导出、恢复默认、持久化与页面范围控制；高级设置默认折叠。
- 完善表单可访问名称、preset 状态与折叠语义，修复主题 select 的可访问名称问题。
- 优化 Silk 动态背景生命周期与兼容处理，动效关闭、路由切换和 reload 后不残留背景 Canvas。

- 增加关键场景浏览器回归，覆盖 Canvas 生命周期、路由切换、动效开关、配置恢复与多视口体验。

影响范围：前端视觉、Appearance Center 与自动化验证；不修改后端 API、权限、Workflow Engine、Socket.IO、Yjs 或数据库。

## 兼容性与范围

近期升级仅调整前端视觉、交互和版本记录展示，不修改后端 API、数据库、权限系统、Workflow Engine、Socket.IO、Yjs 或 Creator Agent。

## 版本来源

- 工程版本以 `package.json` 为唯一来源。
- Vite 在构建时将版本注入为 `__APP_VERSION__`。
- 系统更新提示与“系统更新说明”读取 `src/data/changelog.ts`。
- “关于系统”页面读取相同的 `__APP_VERSION__`，确保代码版本、弹窗版本和文档版本一致。
