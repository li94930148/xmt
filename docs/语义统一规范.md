# 语义统一规范

本文档用于冻结 XMT 当前核心语义，避免后续在内容字段、工作流事实来源和编辑器输出格式上继续分叉。

## 内容字段语义

### 唯一正文源

`production.content` 是当前系统唯一可靠的创作正文源。

1. 数据格式为 HTML string。
2. 编辑器写入和页面保存均应围绕该字段理解。
3. `content_markdown` 与 `content_json` 不得反向覆盖 `production.content`。

### 创作资料草稿

`production_material_drafts.content_html` 是按创作记录保存的独立资料整理草稿，不是第二份正式正文，也不会自动写入 `production.content`。从资料库加入资料时，草稿同时保留插入文本与可点击来源链接；只有用户明确选择“引用到正文”，来源正文和链接才插入正式稿。存量草稿没有链接时不猜测来源。

添加资料必须建立在本记录资料草稿读取成功且编辑器就绪的基础上；读取失败/尚未读取不能以空值拼接替代。插入或引用在途保护来源选择和关闭，失败保留原草稿、正文和选择；两种保存范围继续独立。

### Topic 字段

`topics.outline` 是选题大纲 / 剧本大纲字段，可作为 Production 初始内容来源。

`topics.description` 是选题描述字段，用于表达背景、目标、说明和补充信息。

二者均属于选题阶段内容，不是 Production 创建后的实时引用源。

选题大纲显式版本保存在 `workflow_document_versions` 的 `topic_outline` 记录中，仅用于历史查看；当前大纲仍以 `topics.outline` 为准。普通保存不生成版本，只有用户明确选择小版本或大版本才保存快照。首次建立历史时记录当前内容为基线，但不为旧内容虚构时间或操作人。

Production 初次由选题大纲创建时，`production_origin_snapshots.source_content_snapshot` 保存被复制的 `topics.outline` 原文，作为创建来源的可核对凭据，不是正文真源。后续大纲和创作正文各自修改都不会重写该快照；只有当来源原文与唯一一条非基线显式版本完全相同时，`source_outline_version` 才记录其版本号。无历史、仅有基线或相同正文对应多个显式版本时不猜测版本；旧稿没有来源/版本记录时不得用当前大纲补猜。

### Shooting 字段

`shooting.script_content` 是拍摄阶段本地剧本内容。

1. 有本字段时优先使用本阶段内容。
2. `null` / `undefined` 表示尚未建立本阶段独立稿，可回退到 Production 内容；空字符串表示用户已保存的空白分支，不得回退。
3. 保存后只写 Shooting 本阶段，不回写 Production。
4. `script_source_production_id` 与 `script_source_version` 成对记录首次保存时所引用的已审核创作稿及版本；来源写入后不可静默更换。
5. 迁移不推测补写历史独立稿来源；旧本地稿缺少来源时明确视为未记录。
6. 被阶段稿引用的历史版本不会被自动历史清理，仍有来源引用的创作记录不能删除。
7. `workflow_document_versions` 的来源字段逐版本保存创作稿 ID/版本；历史列表只能展示该历史行明确记载的关联，缺失时不得用当前剧本来源推断。

拍摄剧本显式版本保存在 `workflow_document_versions` 的 `shooting_script` 记录中，仅用于历史查看；当前内容仍以 `shooting.script_content` 为准。普通保存不生成版本，首次显式版本保留当前文本基线且不推测历史时间/操作人。

### Publishing 字段

`publishing.script_content` 是发布阶段本地发布内容。

1. 有本字段时优先使用发布阶段内容。
2. `null` / `undefined` 表示尚未建立本阶段独立稿，可回退到 Production 内容；空字符串表示用户已保存的空白分支，不得回退。
3. 保存后只写 Publishing 本阶段，不回写 Shooting 或 Production。
4. `script_source_production_id` 与 `script_source_version` 成对记录首次保存时所引用的已审核创作稿及版本；来源写入后不可静默更换。
5. 迁移不推测补写历史独立稿来源；旧本地稿缺少来源时明确视为未记录。
6. 已发布归档保存准确的来源正文快照；即使后续历史维护变化，归档内容仍可追溯。
7. `workflow_document_versions` 的来源字段逐版本保存创作稿 ID/版本；历史列表只能展示该历史行明确记载的关联，缺失时不得用当前剧本来源推断。

发布文稿显式版本保存在 `workflow_document_versions` 的 `publishing_script` 记录中，仅用于历史查看；当前内容仍以 `publishing.script_content` 为准。普通保存不生成版本，首次显式版本保留当前文本基线且不推测历史时间/操作人。

“已完成”发布归档仍按选题保存一份可更新的最新快照，包含当前发布文稿正文和准确的来源创作快照，但不替代逐版本历史。显式发布文稿版本写入后，若选题存在已发布记录，服务端会刷新该归档；归档写入失败与主稿保存分别反馈，可之后只重试归档同步。

### Publishing 与抖音作品

`publishing_douyin_links` 只表达发布记录与 `douyin_works` 的一对一身份映射。

1. 关联不改变 `publishing.script_content` 的内容源地位，也不反写发布稿件原始平台、状态、排期或指标。
2. 发布管理展示已关联记录时，发布时间、发布状态、播放、点赞、分享和评论以 `douyin_works` 为准。
3. 标题只是自动匹配线索，不是删除、合并或覆盖业务记录的依据；歧义结果必须人工确认。
4. 未关联或解除关联的记录继续沿用 Publishing 与 Analytics 原有口径。

## 非主数据源字段

以下字段均为非主数据源，禁止作为 canonical：

1. `content_markdown`
2. `content_json`
3. `outline_markdown`
4. `outline_json`

这些字段当前只可视为兼容、过渡或冗余字段。后续如需升级为可靠结构化内容，必须单独设计迁移、回填、校验和回滚策略。

## Workflow 事实类型

当前系统中的 workflow 事实来源分为四类：

1. `workflow_shadow_logs` = 观测事实，用于记录 policy / decision / strict gate 相关运行上下文。
2. `approval_records` = 业务事实，用于表达审批业务结果和历史记录。
3. `decision engine` = 推导事实，用于从观测数据中推导风险、建议和置信度。
4. `policy.ts` = 规则事实，用于表达当前允许的状态转换、审批人规则和配置规则。

## 统一原则

1. 内容字段以 HTML string 为当前主格式。
2. Workflow 观测事实不替代业务事实。
3. 推导事实不替代规则事实。
4. 规则事实不直接改写历史业务事实。
5. 后续治理必须先明确语义来源，再修改实现。

## Collaboration 语义

`collaborationKey` 是编辑器协作文档的运行时唯一标识，不是数据库主键字段，也不新增数据库结构。

当前约定：

1. 创作管理编辑器：`production:{productionId}`，最终保存到 `production.content`。
2. 成片制作编辑器：`shooting:{shootingId}`，最终保存到 `shooting.script_content`。
3. realtime editing is ephemeral state：在线用户、光标、选区、typing、Yjs 增量同步状态只存在于运行时。
4. 数据库仍只保存业务最终内容，不保存协作 presence、awareness 或临时 CRDT room 状态。
5. 冲突处理以 CRDT merge 为主，断线后的最终业务落库遵循现有 API 的 last write wins 行为。
